一、总体任务

你现在担任 Definitio 原生 GIS 运行时的首席工程修复负责人。

本任务目标不是增加功能数量、重构整个架构或追求测试通过率，而是从第一性原理出发，修复系统在空间正确性、权限控制、执行状态、证据真实性和可靠性验证方面的已知或同源缺陷。

最终目标：确保系统不会在实际 GIS 结果错误、未授权副作用发生、外部操作状态未知或证据失效时，错误地向 Agent 宣告成功。

执行以下原则：

1. 先审查真实源码、测试、协议及运行证据，再制定具体修改方案。历史报告中的缺陷必须在当前版本重新验证，不预设尚未修复。
2. 对每个问题建立"根因 → 修复 → 反例 → 回归 → 证据"的完整闭环。
3. 优先修复共用验证器、授权检查和提交状态管理等同源问题，不采用针对单一测试输入的硬编码补丁。
4. 低风险、范围内、可逆、不改变公共契约的修复可以直接实施。
5. 涉及破坏性操作、协议不兼容、架构大改、真实外部写入、付费调用、生产部署或冻结研究设计变更，必须先提交决策请求。
6. 允许自动化代理分工，但每一项验收必须有可复核的实际证据。不能以另一个 Agent 的口头判断替代证据。

三、Phase 1：P0 空间语义正确性修复

P0-01 Buffer 验证器

攻击目标：错误距离、错误位置或错误形状的缓冲结果仍可能通过验证。

行动：

- 审查 Buffer 的输入约束、CRS、距离单位和实际验证谓词。
- 使用历史约 1.4 公里偏移面反例重新测试。
- 验证非空结果、空间关系、距离、面积和适用的几何容差。
- 覆盖 Point、MultiPoint、LineString、Polygon、空几何及合法边界情况。
- 使用解析真值与尽可能独立的 Oracle 交叉检查。
- 检查错误接受和合法结果误拒绝两个方向。

验收：历史错误缓冲结果必须被拒绝，合法 MultiPoint 缓冲不得被无依据拒绝，新增边界测试通过。

P0-02 Clip 验证器

攻击目标：错误裁剪、错误区域或错误属性结果被接受。

行动：

- 检查实际输出与输入几何、裁剪区域的集合关系。
- 验证输出几何、拓扑和属性保留规则。
- 覆盖空交集、重复属性、边界相切、多部件几何和无效几何。
- 不能仅依赖输出类型、要素数量或文件存在判断正确性。

验收：错误裁剪反例被检出，已知合法重复属性案例正确通过。

P0-03 Join 验证器

攻击目标：属性连接结果错配但仍被认证成功。

行动：

- 验证连接键、字段来源和匹配关系。
- 覆盖一对一、一对多、多对多、重复键、空值和缺失键。
- 验证真实记录对应关系，而不仅是字段集合或记录总数。
- 补充错误属性排列及错误字段映射的负例。

验收：历史错误连接反例不再放行；合法连接边界不出现新增误拒绝。

P0-04 同源空间验证器审查

沿 Buffer、Clip、Join 的调用链，检查是否存在其他运算复用相同的不充分验证逻辑。

优先审查：

- Reproject
- Intersect
- Union
- Dissolve
- Spatial Join
- Raster Operations

这些是同源风险检查范围，不代表它们已确认存在缺陷。发现新问题时先构造反例并登记，再决定修复。

四、Phase 2：P0 授权与副作用控制

P0-05 对象级授权边界

复现并修复历史"有限写入权限下可越界导出"的问题。

重点检查：

- 数据集授权与文件系统写入是否被混淆。
- 导出目标是否经过实际路径解析和权限判定。
- 路径穿越、符号链接、Windows Junction、UNC 路径、大小写差异及规范化问题。
- 授权撤销后是否仍可执行。
- 多步骤任务是否使用过期授权。
- dry-run 是否可能产生真实持久副作用。

要求权限判定绑定到实际主体、对象、动作、有效范围和版本，不允许仅凭自然语言授权描述决定执行权限。

验收：所有已知越权反例均被拒绝；合法授权操作仍能正常完成。

P0-06 外部写入及执行状态真实性

修复历史"外部写入已发生但系统报告未执行或已回滚"的问题。

必须区分：

- COMMITTED：已确认提交。
- NOT_COMMITTED：已确认未提交。
- UNKNOWN：操作是否提交尚无法确认。

网络超时、响应解析失败、进程中断不能自动等同于操作失败或回滚成功。

对可能重复产生副作用的操作，优先检查是否支持幂等键、操作 ID 或外部状态查询。无法确认时必须保留 UNKNOWN，并阻止不安全的自动重试。

若现有公共协议无法表达该状态，不得擅自破坏协议兼容性；先提出兼容映射或版本化方案，等待批准。

验收：历史外部写入反例能够准确报告真实执行状态；不存在已知路径把未知执行误报为成功回滚。

五、Phase 3：P0/P1 证据与状态一致性

P0-07 产物状态绑定

修复历史"产物已删除但仍被报告已确认"的问题。

行动：

- 检查验证结果绑定的是文件路径、对象标识、版本还是实际内容。
- 对适用对象记录版本号、哈希或等价的不可混淆标识。
- 在提交或引用旧验证结果前重新核对状态。
- 处理对象删除、修改、替换、重命名和缓存过期。
- 不允许旧的验证成功回执无条件证明当前对象仍然正确。

P1-08 Preview 与 Commit 一致性

检查 dry-run 与实际执行之间的状态变化。

设计并测试：

- 预演后修改输入数据。
- 预演后撤销授权。
- 预演后替换输出位置已有对象。
- 预演后修改执行参数或依赖。

若关键状态变化，必须拒绝直接沿用旧预演结果或重新执行必要检查。

P1-09 证据信封加固

检查证据信封是否能够对应：

- 输入及其版本
- 操作参数
- 实际输出
- 验证谓词与结果
- 授权状态
- 实际副作用
- 最终执行状态

不能因为工具返回 "success=true" 就生成"GIS 结果已验证正确"的声明。

优先复用现有证据信封与状态模型，仅补足真实缺失的约束。

六、Phase 4：P1 误拒绝及 GIS 边界修复

重新检查历史记录中的合法结果误拒绝：

1. MultiPoint Buffer。
2. 含重复属性的 Clip。
3. GDAL 背光坡面阴影。
4. 空几何 Reproject。

同时增加具有代表性的 CRS 单位、轴顺序、无效几何、空输出、浮点容差和栅格 NoData 测试。

每项均同时记录：

- 错误接受数与分母。
- 正确拒绝数与分母。
- 错误拒绝数与分母。
- 正确完成数与分母。
- 无法判定数及原因。

禁止通过扩大容差到失去实际意义的程度来消除失败。

七、Phase 5：红队回归与独立验证

建立一套独立于正常成功路径的对抗性回归。

最低要求：

- 完整复跑历史 13 个反例。
- 完整复跑历史针对性回归与 G1 路径守卫。
- 修复后运行受影响模块测试和全量回归。
- 每个修复至少包含原始反例、合法正例和同源边界例。
- 抽查输入、输出、日志与持久状态，不能只检查退出码。
- 运行相同输入的重复执行测试，并检查状态泄漏。
- 用未参与修复调参的保留反例验证是否存在对特定测试过拟合。

检查独立 Oracle 是否与被测验证器复用了同一个会产生共同错误的底层假设。

保留现有 10 项环境阻塞的真实状态，不允许将 SKIP、BLOCKED、UNKNOWN 统计为 PASS。

严禁：

- 删除失败测试以提高通过率。
- 降低断言强度或容差来掩盖缺陷。
- 用伪造日志代替运行记录。
- 将多轮合成结果冒充一次全量通过。
- 把未复现的历史问题擅自标记为已解决。

八、主动扩展审查

完成明确修复之外，主动沿共享实现继续查找隐藏缺陷。

重点审查：

- 验证器之间共享的错误谓词。
- 数据集句柄、缓存与版本漂移。
- 授权检查与真实执行之间的竞态条件。
- 外部操作的幂等性与重试行为。
- 证据信封与实际持久状态的矛盾。
- 错误码、日志、Agent 可见输出之间的不一致。
- 工具发现层与执行层参数名称或默认值不一致。

新发现的问题必须提供最小可复现案例，不允许仅凭推测认定已经存在漏洞。

对于不改变核心架构、低风险且可逆的同源修复，可以直接完成并记录；对于超出此次整改边界的问题，列入待决清单，不擅自扩大施工范围。

十一、完成标准

只有满足以下条件，才能申请整改完成验收：

- 历史 P0 反例均已经在当前代码上复验并得到正确处理。
